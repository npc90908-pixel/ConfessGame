# A Journey to Your Heart

> Sebuah petualangan 3D kecil, dari aku untukmu.
> An interactive, story-driven 3D web experience that walks someone you love through five dreamlike worlds — and ends with a question.

Built with **Next.js 16 · React 19 · Three.js / React Three Fiber · GSAP · Zustand · Tailwind v4**. Runs in any modern browser, desktop or mobile, with no account, no backend and no third-party assets — every sound and texture is generated by scripts in this repository.

---

## The journey

| Chapter | World | What happens |
| --- | --- | --- |
| 1 · Dunia yang Asing | Sky Island | Wake on a floating island, read the first letter, gather three lights, open the portal |
| 2 · Taman Kenangan | Memory Garden | Pick five flowers, view five floating memories, offer the flowers to the memory tree |
| 3 · Lautan Perasaan | Silent Ocean | Board the boat, sail to the light, find three bottled messages, connect the stars |
| 4 · Kastil Kata-kata | Forgotten Castle | Find three keys, unlock three letter fragments, enter the heart chamber, read *the* letter |
| 5 · Tujuan Terakhir | Final Garden | Follow the glowing path, revisit everything you found, open the gift, answer the question |

25 scenes in total, each with a tiny objective, dialogue and a cinematic or two. Progress auto-saves to `localStorage`, so the recipient can close the tab and come back.

## Quick start

```bash
npm install
npm run dev          # http://localhost:3000
```

```bash
npm run check        # typecheck + lint + tests + production build
npm run build && npm start
```

Requires Node 20+.

## Make it yours

Everything personal lives in **one file**: [`src/config/story.ts`](src/config/story.ts).

- `senderName`, `recipientName`, `title`, `tagline`
- every letter, dialogue line, bottled message, key description and letter fragment
- the five memories (`title`, `caption`, `date`, `image`)
- the proposal question and both answers' endings
- accent colours, animation speed, puzzle difficulty

The config is validated against a Zod schema on boot (`src/config/schema.ts`), so a typo surfaces as a clear error instead of a broken scene.

### Replacing the memory photos

Drop your own pictures into `public/memories/` as `memory-01.webp` … `memory-05.webp` (any aspect ratio — they're shown as polaroids and in a modal). The shipped images are illustrated placeholders produced by `scripts/generate-textures.py`.

### Regenerating audio and textures

All audio (8 music loops, 5 ambience beds, 28 sound effects) and textures (particle sprites, noise/paper/water tiles, memory cards, social card) are **synthesised procedurally** — the repository contains no third-party samples.

```bash
pip install numpy pillow soundfile lameenc
npm run assets:audio      # → public/audio/**/*.{ogg,mp3}
npm run assets:textures   # → public/{particles,textures,memories,images}
```

Tweak a melody in `scripts/generate-audio.py` (chord progressions, instruments and effects are a few lines each) and re-run; the game picks up the new files automatically.

## Controls

| Action | Desktop | Mobile |
| --- | --- | --- |
| Move / steer boat | `W A S D` or arrows | left joystick |
| Look | mouse drag | drag right side |
| Interact | `E` / `Space` / click | tap the prompt |
| Run | `Shift` | — |
| Inventory | `I` | bag button |
| Pause / settings | `Esc` | pause button |
| Skip cinematic | `Esc` / `Space` | tap "skip" |

A quality tier (low / medium / high) is picked automatically from the device and can be changed in settings; it controls DPR, shadows, bloom, depth of field, ambient occlusion and particle density.

## Architecture

```
src/
├─ app/                    Next.js shell (static), fonts, metadata
├─ components/
│  ├─ game/                Canvas, HUD, menus, mobile controls, loading/boot
│  ├─ story/               Letters, memories, bottles, fragments, star puzzle, proposal, endings
│  └─ ui/                  Buttons, panels, icons, typewriter
├─ config/                 story.ts (content) · schema.ts · assets.ts · theme.ts · controls.ts
├─ game/
│  ├─ engine/              GameManager (scene flow), runtime, input, world, fx, interactions
│  ├─ engine/systems/      Player, camera, interaction and look-control systems (useFrame)
│  ├─ scenes/              registry (25 scenes), landmarks, scripts, SceneRouter
│  ├─ scenes/environments/ SkyIsland · MemoryGarden · OceanWorld · CastleWorld · FinalGarden
│  ├─ objects/             Terrain, flora, water, portal, collectibles, sky dome, particles, character
│  ├─ animations/          GSAP camera helpers
│  └─ systems/             Audio manager (Howler), quality tiers, inventory items
├─ lib/                    math, shaders, device detection, preload, i18n
├─ store/                  Zustand stores: progress (persisted), settings, UI
└─ types/
scripts/                   generate-audio.py · generate-textures.py · synth.py
tests/                     Vitest suite (story schema, scene graph, assets, inventory, math, save data)
```

Design notes:

- **One persistent `<Canvas>`.** Environments are lazy-loaded React components routed by `SceneRouter`; chapter changes crossfade behind a veil while the next world mounts and reports `notifyEnvironmentReady`.
- **Hot state lives outside React.** Player, camera rig, input and the interaction registry are plain objects read in `useFrame`; GSAP timelines drive the camera and `fx` values during cinematics. React/Zustand only handle UI and persisted progress.
- **Scenes are data.** `scenes/registry.ts` declares every scene (chapter, kind, objective, spawn, next); `scenes/scripts.ts` holds the per-scene cinematic/dialogue scripts; environments only expose interactables and proximity triggers.
- **Boat mode.** The ocean world switches the player into a physics-light boat controller (throttle / steering, wave bobbing from the same `waterHeightAt` function the water shader uses) with a dedicated camera mode.

## Deploying

The app is a static shell plus client bundles — it deploys to Vercel with zero configuration:

```bash
npx vercel
```

Set `NEXT_PUBLIC_SITE_URL` to your production URL so social cards resolve correctly. Generated assets under `public/` are served with immutable cache headers (see `next.config.ts`).

## Tests

`npm test` runs everything headlessly in about a minute — no browser needed:

| Suite | What it proves |
| --- | --- |
| `tests/*.test.ts` | story content is complete, scene registry is consistent, every asset in the manifest exists, inventory/progress rules |
| `tests/shaders.test.ts` | every custom GLSL program compiles with the Khronos reference compiler, assembled exactly as three.js feeds it to WebGL 2 |
| `tests/smoke/environments.test.tsx` | all five 3D worlds mount with the React Three Fiber test renderer and report ready |
| `tests/smoke/walkthrough.test.ts` | a headless `GameManager` plays title → ending (100 % completion), restarts a chapter, answers "not yet", resumes a checkpoint |
| `tests/smoke/gameplay.test.tsx` | each chapter is played *inside its real environment*: teleport to landmarks, trigger the actual interactables, collect, solve, finish |
| `tests/ui/overlays.test.tsx` | the HTML layer in jsdom: title screen, every overlay, letters, proposal buttons, dialogue stepping, HUD objective, toasts, pause/resume |

Run a single suite with `npx vitest run tests/smoke/gameplay.test.tsx`.
